# 一个经过验证的 21 阶 tournament 反例

[US English](README.md) | [CN 中文说明](README_zh.md)

本包给出一张 21 阶 tournament，其中没有任何 strong Seymour
顶点。对每个顶点 \(x\)，从 \(N^+(x)\) 到严格二阶出邻域
\(N^{++}(x)\) 的二部图都不存在饱和 \(N^+(x)\) 的匹配。

该构造把本仓库中的显式反例上界从 23 阶降到了 21 阶；但仅凭这张
图，还不能断言 21 就是最小阶数。

## 反例

邻接矩阵位于
[`data/adjacency_matrix.txt`](data/adjacency_matrix.txt)。其中
\(A_{uv}=1\) 表示 \(u\to v\)。以 LF 结尾的规范文件 SHA-256 为：

```text
9773f6f889db845bd727c726988b7017a99a8f3bff79896fed214b2aed9a6d5e
```

21 个顶点的出度依次为：

```text
9,10,10,9,9,9,10,10,11,12,9,9,9,11,11,11,9,10,10,10,12
```

独立计算得到的最大匹配数依次为：

```text
8,9,9,8,8,8,8,9,8,8,8,8,8,9,9,9,8,9,9,9,8
```

每个匹配数都严格小于对应出度，所以 21 个顶点全部不是 strong。

## 验证

包内包含两套实现方式明显不同的检查器：

- `src/verify.py` 使用有限状态动态规划精确计算最大匹配，并穷举
  所有左侧子集寻找 Hall 缺陷；
- `src/verify.cpp` 使用 Kuhn 增广路算法，并独立穷举全部左侧子集。

每个顶点的匹配数和显式 Hall 证书记录在
[`data/full_verification.json`](data/full_verification.json) 中。

在 Ubuntu 或 WSL 中运行：

```bash
./run_all.sh
```

脚本会核对哈希、重新编译 C++ 检查器、运行两套实现，并把重新生成
的 JSON 与公开结果逐字节比较。

## 发现过程与当前边界

精确的 22 阶 SAT 搜索先在 \(d=9,p=2\) 分支中找到一个模型。该模型
含有一个支配其余所有顶点的 universal source；删掉该顶点后，得到
本包中的 21 阶 tournament。重新逐顶点计算后，剩余 21 个顶点仍然
全部不是 strong。

结合此前已经验证的 13 阶及以下正面结果，目前得到：

\[
14\le n_{\min}\le 21.
\]

20 阶精确搜索与本反例声明严格分开：求解超时或启发式搜索未找到
反例，都不会被表述成“不存在证明”。
